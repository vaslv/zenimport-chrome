# L7 durable capture review

Scope: named local capture commands and bank observations, the existing coordinator
and both real connector drivers against synthetic bank pages. Local product routing
and financial SDK writes remain disabled.

Two independent read-only passes compared the dirty checkpoint to Python capture,
record identity, ownership and portable proof behavior. Fixtures were inspected in
summary mode. These are independent same-model reviews; an external cross-model
CLI pass is unavailable in this environment and is not counted as passed.

Findings fixed:

- Normalize UUID path values before lookups, not merely validate their spelling.
  Native uppercase UUID commands exercise get, lease, page, complete and stop.
- Preserve Python's collecting-before-planned aggregate state for a multi-window
  account. The closed state membership list is separate from display priority.
- Reserve legacy-v12 for verified archive imports. Live discovery/capabilities,
  page preflight and the low-level record writer reject that marker before any
  facts are committed. The Python source defect is fixed in backend 40f89dd;
  rejected input followed by valid capture and portable export is a native test.
- Derive delivery progress from saved facts without invoking a financial API.
  Empty completed history is complete; unresolved delivery/settings evidence
  blocks delivery without blocking bank capture. This matches refresh_status.

The final independent passes reported no further confirmed findings. Actual
Python/browser parity compares all 18 capture/account tables across out-of-order
pages, repeated ACKs and a second changed observation, including exact raw JSON,
page digest, amount text, coverage and immutable revision references. Only freshly
allocated local storage/audit UUIDs are mapped by documented semantic identities;
no attempted payload or ZenMoney identity is normalized away.

Completion uses a count proof: writers constrain page_number to 1..N and keep N
immutable; pages and their exact unique record sets commit atomically. Therefore
N committed pages plus the declared total record count prove the same complete
sequence without materializing up to 10,000 raw page bodies. Imported page graphs
are validated separately by the portable proof. Reviewers checked this argument.

Native checks cover expiry, stale/wrong workers, wrong job/interval, context changes,
quota rollback, lost worker replies, settings cancellation, partial cancellation,
500-record pages, duplicate identities and exportability. The unchanged bank DOM
drivers and coordinator are exercised for BIDV/VietinBank, empty and nonempty
history, with the real IDB page owner. There is no bank product UI injection.

Still outside L7: downstream reconciliation/prediction/report projection, durable
writer, guarded imported first-sync activation and product mode selection. The
capture job view currently enumerates matching bank observations within one
transaction; the final 100k acceptance gate must measure this path and bound it
if it exceeds the existing transaction budget. No large-history performance claim
is inferred from the 500-record page test. Results are recorded in progress.md.
