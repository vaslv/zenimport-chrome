# L9 — create-only delivery and recovery exit review

Scope: committed authorization/outbox/sender checkpoints plus durable cycle,
backoff, status refresh and alarm recovery. API and adversarial reviewers completed
independent final passes with no remaining findings. The primary agent executed
Docker tests; the adversarial reviewer inspected fixture changes in summary mode.
External cross-model CLI coverage remains unavailable, not a successful review.

Earlier checkpoint findings and fixes are documented in l9-authorization,
l9-intents, l9-outbox and l9-sender reviews. Final scheduler findings fixed:

1. A one-shot alarm scheduled only after run could disappear when Chrome stopped
   the worker. A periodic watchdog is installed before execution; restart checks
   recreate it. Idle checks make no financial API request.
2. Overlapping restores could clear a newer alarm. Ticketed serialization drains
   all requested restores, including requests overlapping promise completion.
3. Only the first 20 jobs were refreshed. Financial evidence changes now enqueue
   a private status sweep atomically. Each page updates at most 20 jobs before a
   compare-and-ack checkpoint; a crash repeats the same harmless status reads.
   Status-only continuation requires no SDK request.
4. Empty/already-delivered capture completion lacked financial state changes and
   could miss the sweep. Accepted authorization work also queues it atomically.
5. An eligible but blocked pending intent retried immediately. No-send pending
   uses the reference 15/30/60/120/240/300-second backoff; successful batches and
   status-only pages may continue immediately.

Each cycle creates at most 20 operations. A watchdog wake runs at most three
cycles, checking elapsed time after each. A 180-second native cycle lease prevents
parallel cycles; the independently fenced 60-second outbox grant owns the actual
write. Lease expiry never grants another create for an attempted UUID. Credentials,
settings, mirror, Root and migration fences are rechecked before dispatch.

SDK replies can be incomplete. Explicit transaction reads verify the original
UUID; edited existence confirms delivery and deletion permanently suppresses it.
Absence, HTTP 400, timeout, worker death and unknown replies cannot authorize blind
retry. A persistent fake service records exact creates across browser restarts.

Private job sweeps, work caches, leases and alarms are not portable financial
facts. Immutable attempts, exact payloads, authorization/capture revisions,
actual-account proofs, receipts and tombstones are portable and independently
validated by the Python graph validator, both before and after SDK reply apply.
