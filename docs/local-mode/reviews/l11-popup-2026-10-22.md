# L11 independent popup review

Scope: built-product entry point, peer setup sections, local token drafts and
verification, account/report compatibility, portable export/restore and mode
transfer controls. Review-only independent specialist: `l11_final_review`.

Fixed findings:

- A successful credential commit followed by a failed first catalog read now
  reloads application state in `finally`. The user can retry the catalog in the
  same popup after the durable mirror cooldown without entering the token again.
- A late draft read cannot overwrite freshly entered browser-return credentials.
- A ready server backup says it is ready to download, while retaining the existing
  exclusion of another storage operation until acknowledgement/cleanup.
- Rate-limit, mirror cooldown and mirror-busy codes have accurate user messages.
- Completed remote recovery retains a useful completion message after cleanup;
  it does not claim that no later synchronization has sent transactions.

Final focused and critical-path review: **NO FINDINGS**. The reviewer checked
outbound SDK writes, immutable dispatch intent, explicit authorization, runtime
and RPC fencing, mode selection and first-sync hold. Static review does not replace
Docker evidence. Cross-model CLI review was unavailable; no such coverage is claimed.

Tests cover setup, invalid token, protected drafts, token removal, temporary first
catalog failure, backup download/acknowledgement, keyboard focus/labels, 390 px
layout, old remote popup behavior and read-only discrepancies. Actual Python
integration additionally tests capture, export/restore, repeated synchronization,
mobile deletion, pagination, multiple accounts and bank-context changes.
The consolidated evidence is recorded in the stage progress/release acceptance log.
