# L8.1 pure matching checkpoint

Scope: exact subset proofs, two-sided discrepancy comparison, reference-first
singles, deterministic multiplicity and split/settlement groups. No storage
mutation, financial API call, ownership recovery or category learning is enabled.
Canonical plain decimal strings are the frozen input boundary; SDK/mirror numeric
spellings must pass the existing exact codec before entering this domain.

Independent API and adversarial readers compared the full source to actual Python
existing.py and discrepancies.py. Fixtures were reviewed in summary mode. Both
final reviews found no confirmed defect. A suggested JavaScript end-anchor
finding was withdrawn after runtime verification: the old regex already rejected
trailing LF without multiline mode. The explicit full-match spelling and boundary
regressions are defensive clarity, not a reproduced production bug fix. No
cross-model review is claimed.

Proofs preserve per-target ownership: the same transfer can match both independent
bank legs, but a leg is consumed once. Unknown historical ownership, exclusions,
hold and shared target restrictions are respected. References require unique
exact day/account/instrument/signed amount corroboration. Amount-order pairing
stays labelled day_amount_order; it is not category evidence.

Combination matching allows at most 16 elements and 20,000 shared search steps per
day. Budget exhaustion discards all that day's proposals, including previously
found ones. Report comparison uses preferred identities only after current amount
validation and reports both unmatched sides even when daily totals balance.

The actual Python/native browser adapters compare 500 subset/report vectors and
200 reference/multiplicity/group vectors. The SQL adapter uses only the source
functions' queried inputs; it is not a persistent FK/graph acceptance claim. The
separate native repository suite proves durable graph rules. Initial harness
failures (scientific Decimal display versus canonical plain domain input, then
Python tuple versus JSON list shape) were corrected without changing financial
expectations. The corrected 700-vector comparison passed.

Still pending in L8: persisted ownership/backfill and late transfer recovery,
category evidence/prediction, complete-coverage report assembly and revision-
fenced derived writes. The product remains remote-only and has no local SDK writer.
