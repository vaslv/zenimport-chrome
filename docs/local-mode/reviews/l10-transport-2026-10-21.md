# L10.1 — authenticated participant transport and fresh server identity

Independent API review of the Python identity endpoint and adversarial review of
the TypeScript gateway ended with no remaining findings. Cross-model CLI review
is still unavailable; primary-agent Docker tests provide execution evidence.

The additive portable-v2 identity endpoint performs a fresh SDK read into a private
temporary database, under exclusive migration/writer ownership. It returns owner
IDs and participant capabilities without publishing financial rows, a cursor or
clearing any hold. Token/response failures return stable redacted errors.

The browser gateway bounds JSON to 1 MiB and archive chunks to 262144 bytes,
verifies checksums and receipt integrity, preserves null fields and binds replies
to the command, request, switch, epoch and peer/dataset metadata. Task IDs, kinds
and switch IDs are checked for command/finalize/retry replies. Commands do not
retry automatically; later orchestration must recover by status and durable IDs.

Fixed review findings: valid but unrelated receipts/tasks were previously accepted;
peer binding now includes both directions of a supplied peer receipt. Native
browser testing also exposed fetch being called with an invalid object receiver;
the gateway now invokes it without a receiver. A test-helper duplicate keyword
was corrected separately. Unit mocks did not substitute for the browser test.

Docker: 231 unit/contracts plus strict/generated checks; 32 Python portable API/
service/contracts tests in 11.98s; actual installed Chrome to isolated Python HTTP
identity/auth/permission test passed in 3.29s. Python runs emitted the preexisting
Starlette deprecation warning. Logs: /tmp/zenimport-l10-identity*.log and
/tmp/zenimport-l10-remote-*.log.

This is a transport checkpoint, not completed migration or local product routing.
