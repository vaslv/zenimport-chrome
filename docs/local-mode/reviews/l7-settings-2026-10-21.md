# L7 account settings checkpoint review

Scope: the local account configuration owner and supporting indexed lookups,
without product routing, capture orchestration or a ZenMoney writer.

An independent API reviewer compared the implementation to Python accounts.py;
an independent red-team reviewer inspected hold ownership, restart/replay,
migration exclusion and attempted-data preservation. Reviewers were read-only;
Docker checks were run by the implementation agent. No cross-model pass is claimed.

Findings fixed before this checkpoint:

- The first 100k test exposed a bank-ID versus ZenMoney-primary-ID lookup mistake.
  Delivery reads now use the actual unique bank_id index, preserving input order.
  A separate attempted-prepared regression proves the unknown-outcome barrier.
- The corrected full invalidation took 21.1 seconds. ADR 006 replaces that single
  transaction with a durable exclusive hold and bounded units, without weakening
  the 10-second assertion or allowing partial settings to escape into export.
- Concurrent identical configure/recover could lose the final reply after another
  executor released the hold. Generation-fenced immutable terminal receipts now
  answer those repeats, including the original failure code.
- MAX_INT64 settings_version could acquire a hold and then overflow forever at
  finalization. The next version is now validated before acquisition and stored
  in the operation. Coverage representability is also a preflight concern.
- A connection test assumed random UUID order matched input account order. It now
  identifies the account by source_key, matching both real implementations.

The final red-team recheck found no further confirmed defect in these fixes.
The native suite covers atomic settings/idempotent ACK, missing/stale/wrong-currency
catalogs, old bindings, uncertain and attempted-prepared deliveries, 100k prepared
rows, maximum version, concurrent commands, quota rollback, worker termination and
concurrent configure/recovery. The actual Python adapter compares final discovery,
configuration, renaming and unlink views; its seeded period adapter compares 250
actual planner cases. Logs/results are recorded in progress.md.

Still outside this checkpoint: the privileged catalog-refresh wrapper and product
UI, guarded imported first-sync source initialization, complete capture jobs and
L8–L12. No real data, live API request, push, tag or publication was used.
