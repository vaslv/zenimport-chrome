# L6 independent review

Scope: Chrome changes after `8062afd`, including the new mirror/credential modules
and their native storage/archive integration. Backend projection correction:
`23ae6e9`. This is a private checkpoint, not a publication approval.

The review skill was applied. Six independent specialist agents inspected API
behavior, storage/migration, security, performance, testing and maintainability.
Two further agents performed adversarial/red-team passes. All used the available
inherited model; no cross-model or Claude pass is claimed. Reviewers were
read-only. Native checks were executed separately by the implementation agent.

Accepted findings and fixes:

- Secret candidates could survive interrupted verification. Acknowledged Root
  selection, loser cleanup and epoch-fenced TTL collection now cover that race.
- Permission must also be checked for fresh-cache reads and readiness. Revoked
  permission blocks those paths and a failed fetch cannot bypass the check.
- Rebinding the same token must require full refresh. Durable forceFull now
  prevents an incremental cursor from silently reusing incomplete imported data.
- Native inspection omitted physical scope resolution. It now counts only the
  published projection under the same transaction guard as ordinary readers.
- Large raw-run copies and account catalog reads could load excessive data.
  Raw runs copy one per unit; catalogs read only account/instrument/tag prefixes.
- Small diffs must not copy the entire history. The direct atomic path remains
  bounded by incoming mutations and affected old tags; large affected tag sets
  use unpublished construction with hard-deleted entities omitted.
- Imported awaiting-sync state needs read-only initialization without enabling
  financial writes. A separate restricted mirror transaction preserves that fence.
- Reminder flags differed between the real mirror and archive validators. Both
  validators now follow raw source flags, backed by actual Python projection.
- Prediction invalidation still performed a full history erase. Ready/generation
  now invalidate immediately; a persisted 500-key collector reclaims stale rows.
  A red-team recheck found no further confirmed defect in this correction.

The adversarial compatibility question about reminder flags was investigated:
the actual Python producer already projected them, while both former validators
rejected such a valid export. The old current graph with null contradictory
projections is not treated as valid evidence; the explicit legacy proof remains
unchanged. See local-mirror.md for the policy and remaining later-stage scope.

An extra external Codex CLI review could not start because its app server needed
access outside the process sandbox. It is recorded as unavailable, not passed;
no global permissions/configuration were changed to bypass that restriction.
The independent specialist and adversarial passes above did complete.

Docker evidence is recorded in progress.md after the final runs. No live write,
push, Git tag, release, telemetry upload or production service change occurred.
