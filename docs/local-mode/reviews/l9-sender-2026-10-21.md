# L9.5 — fenced SDK dispatch and atomic reply publication

Independent API/adversarial final reviews: no remaining findings. The external
cross-model CLI remains unavailable; the reviewers did not execute tests.

Fixed findings:

- Delivery reply publication originally used the read-only mirror transaction
  scope, which rejects financial attempt inserts. Only the final delivery path
  now uses the ordinary financial transaction with its stronger authority gate.
  Ordinary read-mirror publication retains its restricted table scope.
- A losing concurrent sender could settle another sender's in-flight request.
  Completion now requires a grant acquired by that invocation. Pre-grant failure
  leaves the durable attempt for deadline recovery; it cannot settle a competitor.

The published SDK is the only HTTP financial client. Exact frozen payloads and
cursor enter one create-only request; the final native grant and synchronous
abort/deadline checks immediately precede fetch. A 400, partial reply or timeout
never permits a new UUID. Reply projection, cursor, immutable journal outcomes and
settled manifest publish atomically; a failed shadow stage remains unpublished.

Synthetic native tests cover normal/partial/large replies, quota rollback,
400/429/500, malformed reply, timeout, settings/credential/permission/expiry fences,
concurrent senders and browser shutdown after the fake remote commit. Final test
counts and logs are recorded in progress.md. No live API or financial product
routing is enabled. Scheduler and full L9 exit gate remain pending.
